Exact public steps

Copied from the competition home page, section “How to compete”, fetched 2026-10-20. The logged-in form was not opened in this session, so this page does not invent field labels for it.

  1. Click “Compete!” in the sidebar on the competition homepage to enroll.
  2. Read the overview and the problem description. The organizers also link an about page.
  3. Download the data from the data tab. Login is required. This repository did not download it.
  4. Create and train a model. The organizers publish a reference solution. It was not executed here.
  5. Generate predictions that match the submission format: one single-band float32 GeoTIFF, EPSG:32611, 100 m, the same bounds as the training data, values in [0, 1]. The problem page says cells outside the bounds should be null or NaN.
  6. Click “Submit” in the sidebar, then “Make new submission”.

If a rule is unclear, the home page says to ask in the competition forum or email gemsprize@nlr.gov. Official rules: DrivenData rules page, which links to HeroX resource 2274.

What to do with a file from this site

  1. Confirm the home-page plate says OK TO SUBMIT. If it says anything else, stop. Today's plate says not to submit.
  2. Download the -zeros.tif named on the plate. Do not upload the -nan.tif twin. The zip is the same zeros file, packed, and is not a better upload.
  3. Check the sha256 of the downloaded file against the sha256 on the plate. If they differ, do not upload.
  4. Submit that GeoTIFF. The problem page requires one single-band file. Keep the note at or under 140 characters and use the name printed on the plate if the form asks for one. This session did not re-open the form, so it does not claim a particular field label.
  5. Record the organizer receipt. Until that receipt exists, the score is not ORGANIZER-CONFIRMED, no matter what a holdout number was.

The error "Predicted values must be in range [0, 1]"

DrivenData rejects a raster whose predicted values are outside [0, 1]. Two different defects produce that same message, and both have been seen in this project family:

  • A nodata sentinel. The competition feature raster uses −3.4028234663852886×1038 as nodata. If that sentinel is copied into a submission, it is not a value in [0, 1], and the portal rejects the file.
  • An actual prediction outside [0, 1], including a NaN if the validator treats NaN as out of range. The problem page also says cells outside the study bounds should be null or NaN. Those two requirements can collide. This site therefore ships an all-finite zeros file as the only upload candidate, and keeps a NaN-outside twin for the page's wording. The twin is not the upload.

Today's zeros file was re-opened from disk: nodata tag null, minimum 0, maximum 1, zero NaN cells, EPSG:32611, 3730×3292, transform (100, 0, 243350, 0, −100, 4508550). That makes the portal range error impossible for this particular file. It does not make the file worth submitting.

What the competition is actually scoring

You submit one single-band float32 GeoTIFF of fault probability, values in [0, 1], on the training grid (EPSG:32611, 100 m, same bounds). The hidden test faults were labeled by experts and are not in the public USGS compilation. The metric is a distance-weighted Tversky index, alpha 0.2, beta 0.8, triangular kernel of 300 m. Near misses get partial credit. The false-negative weight is four times the false-positive weight.

The home page, fetched 2026-10-20, says the same submission is scored twice: once against a private expert-labeled test set for the Initial Prize Round ($50,000; top 5 each receive $10,000), and again against an expanded label set built from expert review of all submissions for the Final Prize Round ($250,000; $100,000 / $70,000 / $40,000 / $25,000 / $15,000). Deadline: 3 December 2026, 23:59 UTC.

A file that only redraws the published catalogue is not aimed at the private faults. A file that invents faults with no geological support spends the false-positive weight. Today's file is the second kind of failure on the holdout we can actually run: the discharge axes do not recover withheld catalogue segments better than chance. That holdout is not the private test set.
