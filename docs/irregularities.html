Irregularities

These are defects and limits, not footnotes to skip. Each one changed what this site is willing to claim.

IR-71-DIST-01 — first champion-distance write was inverted

The first forensics call complemented the catalogue mask twice, so it reported a minimum distance of 0 m. That write is void. The published card was remeasured: minimum 223.6 m, median 1,964.7 m, 5.8% of dots within 300 m, 0 dots on the catalogue. Those corrected figures match the independent description on the GEMSDOE32 page. The code path is fixed. The wrong number is not on the site.

IR-71-INCUMBENT-01 — the holdout-best registry file paints the catalogue

calib_hedgev2_01563_sample.tif scores HOLDOUT-DTI 0.270 because it is positive on all 60,988 catalogue pixels, so withheld segments have a false-negative weight of zero. Using it as a discovery bar would force every candidate to redraw the catalogue. The preregistered comparison was still computed and still failed. A separate off-catalogue diagnostic is reported and is also a loss.

IR-71-UNIQ-01 — four registry rasters are not discriminative

Literal 3 px overlap exceeded 0.70 against two lattice rasters, r11_greedy_mp.tif, and r14_union_tips10_lat6.tif. A mass-matched random draw of the same size fired on all four, at equal or higher overlap. Spearman against every checked raster stayed under 0.005. Jaccard with the lattices is about 0.00015. This is the known space-filling-prior failure, not a copy of another method. Overlap with the 0.2778 file is 0.140.

IR-71-TEMPLATE-UNIQ-01 — the shared classifier misses this case

gems57.uniqueness.DENSE_SUPPORT_FRACTION is 0.20. A 5-pixel lattice has about 207,000 dots, which is 4% of the footprint, so it is classified as a dot field even though its 3 px halo covers essentially the whole map. The template was not patched in this session: this branch is not allowed to push a fix into 60GEMSDOE, and a private fork of the gate would hide the disagreement. The random-draw control is disclosed in the run card. A template pull request is the right next fix, and it has not been opened.

IR-71-SAMPLE-01 — the mirrored sample submission is not total fault absence

The problem page describes a sample that predicts total fault absence. The owner mirror sample_submission.tif (sha256 2176d08e485aa2cd2860ce8df539db4faf4d76163b38a4dd8c30a40454d35cbc) has 60,988 ones, and those ones are exactly the catalogue. Its finite mask is the footprint, and that use is valid. Its values are not a template of fault absence. The mirror is not organizer-authenticated.

IR-71-MIRROR-01 — competition rasters are owner mirrors

DrivenData data requires a login. This session did not have one and did not contact the data host. Grid, catalogue, springs, paleo deposits, probes, vents, and the radiometric uint8 stack came from public GitHub mirrors pinned by sha256 in the 60GEMSDOE checkout (template commit b99591ee). A pin proves the bytes match the mirror. It does not prove the mirror matches the organizer's file.

IR-71-LANE-01 — the session prompt did not delimit a method paragraph

The parallel-run protocol says to stay inside "the single method paragraph below." No separate method paragraph was present in the prompt delivered to this session. The lane was taken from the prompt's own scientific instruction — find geothermal-vent evidence for faults the catalogue missed, and do not copy an existing submission — and frozen in the preregistration before scoring. Other sessions already own lidar scarps, auto-context, relay ramps, and chi/knickpoints. This lane does not repeat them.

IR-71-BOARD-01 — prompt leaderboard figures are stale

The prompt cites 0.4413, 0.3774, and 0.3195 as the high score in different sentences. The official page fetched 2026-10-20 shows rank 1 at 0.4413. 0.3774 does not appear in the transcribed top 23. 0.3195 is not the current top. Group snapshots that called 0.3195 a 4 October rank-3 row were not re-verified here.

IR-71-E62-01 — a thermal multiplier on knickpoints was already negative

60GEMSDOE experiment E62 used GDR spring chemistry, paleo deposits, and 2 m probes as a multiplier on a knickpoint lane and lost to a random map. This session did not rerun that lane. It used the same public tables as the seeds of a lineament detector. The null result is consistent with E62 and is not a copy of its raster.
