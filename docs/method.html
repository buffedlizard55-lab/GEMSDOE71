Why the 0.2778 file scores what it scores

Every measurement below was made in this checkout or copied from a page fetched on 2026-10-20. The group's earlier inversion of hidden-set size is not repeated, because that size is not public and was not re-derived here.

The metric, from the problem page

Source: DrivenData competition 306, problem description. Alpha = 0.2, beta = 0.8, triangular kernel k(d) = max(1 − d/300 m, 0).

DTI = TPw / (TPw + 0.2·FPw + 0.8·FNw)

The published worked example is TPw = 3.00, FPw = 1.89, FNw = 2.00, displayed as 0.60. The exact ratio is 3 / 4.978 = 0.60265, which rounds to the displayed 0.60. This repository's metric module matches that arithmetic and matches a brute-force oracle on a synthetic grid.

Algebra, not a score: a non-redundant extra dot with kernel credit k raises DTI only if k > 0.2 × DTI. If a file really sits at 0.2778, that bar is 0.0556 credit per dot. A dot on a mapped fault earns nothing against a test set that excludes mapped faults, and it still pays the false-positive tax. That is why deleting catalogue-adjacent mass can raise a live score without adding any new geology.

Can a new file beat it?

Yes, in principle. The public board already has. Rank 1 on the official leaderboard, fetched 2026-10-20, is xiaofanhu at 0.4413. That is an ORGANIZER-CONFIRMED public row. It is not a score of any file in this repository, and it is not a target this file is projected to reach.

Beating 0.2778, if that owner-reported figure is real, requires more credit per unit of mass: either dots closer to the hidden faults, or fewer wasted dots at the same coverage. Copying the 37,654-dot file is forbidden by the uniqueness rule and would not be new information. Thinning it further is the experiment that family already ran.

This session tested a different mechanism: alignments of hot springs, sinter, travertine, and 2 m temperature anomalies, optionally continued along a magnetic gradient. It is the kind of evidence a field geologist uses to draw a fault the USGS map missed. On the mandated holdout it does not work.

  • Spring density AUC against withheld faults: 0.498. Paleo density: 0.499. The traces themselves: 0.500. Chance.
  • HOLDOUT-DTI of the shipped arm: 0.001538, 95% CI [0.0002, 0.0033], 11321 withheld positives. Paired difference versus a mass-matched random map has a confidence interval that includes zero.
  • True-positive weight was 14.1 against 11321 withheld pixels. Seven hundred and thirty-five dots recovered almost none of the hidden catalogue segments.
  • Overlap with the 0.2778 file is 0.140, so this is not a disguised copy. It is a different map, and a weaker one on this instrument.

The catalogue holdout cannot reward a fault that is absent from the catalogue. A null result here does not prove the axes are geologically empty. It does prove they are not a certified improvement. A few hundred dots cannot cover the fault mass a 37,654-dot file is covering unless almost every dot is a direct hit, and we measured the opposite. That is an argument about coverage, not a projected leaderboard score.

The holdout bar is partly the wrong bar

The highest HOLDOUT-DTI in the local registry is 0.2701 on calib_hedgev2_01563_sample.tif. That file is positive on every one of the 60,988 catalogue pixels, so its false-negative count on withheld catalogue segments is zero. A discovery file that refuses to paint the catalogue cannot beat that number, and should not try. The preregistered gate still fails for an independent reason: we also fail to beat random.

Restricted to registry rasters with zero dots on the catalogue, the best HOLDOUT-DTI is 0.0943. Still an order of magnitude above this file. That comparison is a diagnostic, not a rewritten gate.

Known inversion, remeasured rather than assumed: the owner-reported 0.2778 file scores 0.0037 on this holdout, while a catalogue-covering hedge file scores about 0.270. Live rankings and catalogue-recovery rankings are not the same instrument. Until that is repaired, a holdout win is necessary and not sufficient. This file does not have the necessary part.
